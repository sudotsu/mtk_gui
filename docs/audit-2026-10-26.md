# mtk_gui whole-codebase audit — 2026-10-26

Baseline: commit `ae1d2ac`, 5,840 LOC, 48 files, zero tests.
Line numbers are from that commit unless a phase note says otherwise.

Triggered by a SIGSEGV on exit. The audit found the exit crash is the least
dangerous defect present. Findings are grouped by subsystem; the remediation
order lives in the plan, not here.

---

## A. Crash of record (2026-10-26 19:03:36 CDT)

`mtk-gui` PID 248524, SIGSEGV, `SEGV_MAPERR` at `0x410`.

Path: mouse click → `QAction::triggered` → `QMainWindow::qt_metacall` →
`QWidget::close` → `QWindow::close` → close-event delivery → PySide6 converts
the C++ `QEvent*` into a Python object for the `closeEvent` override
(`main_window.py:1041`) → `Shiboken::Module::get(TypeInitStruct&)` lazily
resolves `QCloseEvent` → `PyObject_GetAttr` → `introduceWrapperType` → fault.

Trigger: `file_menu.addAction("Exit", self.close)` — `main_window.py:136`.
Faulting instruction `movzbl 0x70(%r15)` with `r15 = 0x3a0`; a pointer that
should have been a `PyTypeObject*` held a small integer. `closeEvent`'s body
never ran, so window geometry was not saved.

All Qt in the process came from the venv's bundled PySide6 6.12.0 wheel; no
system `/usr/lib` Qt6 was mapped, so there is no ABI mixing. Not reproducible
in two minimal scripts. Not an Omarchy bug — nothing Omarchy packages was
loaded into the process.

### Confirmation UX as it stood

`ConfirmationDialog` requires typing `YES`, case-insensitive (`confirmation_dialog.py:70, :76`). That is the ceiling of protection for every destructive op. Message quality is the real weakness: "Write to RPMB?" (`main_window.py:695`) names no sector, count or file; "From Directory" — the broadest-impact write mode — says only `"Write matching partition images from {dir}"` (`:464`) and never enumerates what it overwrites. The erase/write warning banners are permanently dismissable via QSettings (`erase_tab.py:33`, `write_tab.py:31`).

## G. Input validation

Unvalidated input reaching the backend:

- **Memory poke data** — no hex validation at all; `"hello"` is accepted. `memory_tab.py:156` → `main_window.py:657` → `da_poke`.
- **RPMB sector/sectors** — passed as raw strings, never ints, call not wrapped in `try`. `rpmb_tab.py:148-153` → `main_window.py:678`.
- **Partition names are editable in the write tree** and sent verbatim to `da_write`. `write_tab.py:198, :232`.
- **Stage2 address parse is uncaught** — `ValueError` becomes an unhandled exception inside a Qt slot. `exploit_tab.py:184-187` → `main_window.py:891`.
- **Serial port is free text** — editable combo, no validation. `device_tab.py:133`.

Asymmetries: erase rejects a negative start sector, read does not (`erase_tab.py:136` vs `read_tab.py:220`). Peek length has no upper bound (`memory_tab.py:147`). IMEI write checks 15 digits but not Luhn, though the read path *does* report checksum validity (`main_window.py:769-773` vs `:754-756`). Read output paths are never checked for existence, writability or free space.

Dead input: `rpmb_tab.py:96-100` collects a 32-byte RPMB auth key that nothing reads; `auth_rpmb()` exists at `mtk_wrapper.py:597` and is never called.

`_parse_imei_hex_params` (`main_window.py:722-732`) is correct validation logic welded to a `QMessageBox` — untestable as written.

## H. Project infrastructure

- **Zero tests.** No `tests/`, no `conftest.py`, no pytest config, no testing dependency in `uv.lock`'s 19 packages.
- **Zero CI.** No `.github/` directory at all.
- No ruff / flake8 / mypy / black / pre-commit / editorconfig config.
- `uv.lock` existed on disk but was **untracked** — no reproducibility for any clone.
- `PySide6>=6.5` unbounded; the resolved Qt version was a function of install date.
- `requires-python = ">=3.9"` was false: `port_detection.py:18` uses `list[...]` in an evaluated annotation and cannot import on 3.9.
- `pyusb` used directly but undeclared; arrived transitively via mtkclient.
- No package-data declared — a built wheel shipped **no `.qss` files**, and `load_stylesheet` returns `""` silently (`theme/__init__.py:19`), so an installed app was unthemed with no error. Masked locally by the editable install.
- `plugins/` is excluded by `include = ["mtk_gui*"]`, so the app-local plugin path is dead for a pip install while the PyInstaller spec handles it correctly — frozen and pip installs diverge.
- `run.py` installed the stdio bridge; `mtk_gui.app:main` (the actual console-script entry point) did not.
- README has no udev rules, no Linux permissions guidance, no chipset prerequisites, no risk disclaimer, no troubleshooting, no "attach a log" instruction. Windows driver setup gets 6 lines; Linux gets zero.

## I. Accessibility and theming

Zero `setShortcut`, `QKeySequence`, `QShortcut`, `setTabOrder`, `setFocusPolicy`,
`setBuddy`, or `setAccessibleName` in the entire project. No menu mnemonics.
47 hardcoded pixel sizes. `QFont("Consolas", 9)` hardcoded in four places.

`theme/colors.py` is imported by exactly one module (`device_tab.py:9`); every
other styled widget re-hardcodes the same hex values inline, so light mode leaves
banners, the status LED, the confirmation text and the server status
dark-themed. `colors.py` has no light-mode palette at all.

`log_panel.py:117` maps "All" and "Debug" to the same filter — one dead menu entry.
`log_panel.py:91` grows `_all_messages` unbounded and re-renders the whole history
on every search keystroke.

Plugin sandboxing (plugins are the owner's own files in his own config dir),
